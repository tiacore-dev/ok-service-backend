# Иерархия категорий работ

Категории работ образуют дерево через самоссылку `work_categories.parent_id`.

## Модель данных

- `parent_id` — `UUID`, `NULL` допускается, внешний ключ на
  `work_categories.work_category_id`, индекс `ix_work_categories_parent_id`.
- `parent_id = NULL` — корневая категория. Глубина вложенности не ограничена.
- Миграция `20261110120000` добавляет колонку, FK и индекс; существующие
  категории остаются корневыми. Downgrade удаляет колонку (иерархия теряется).
- FK без `ON DELETE`: жёсткое удаление категории, у которой есть дочерние,
  отклоняется с `409` (как и при наличии связанных работ). Мягкое удаление
  родителя не затрагивает дочерние категории.

## API

| Endpoint | Поле | Поведение |
|---|---|---|
| `POST /work_categories/add` | `parent_id` (опц., UUID или `null`) | отсутствует или `null` — корневая категория |
| `PATCH /work_categories/{id}/edit` | `parent_id` (опц., UUID или `null`) | ключ отсутствует — родитель не меняется; `null` — перенос в корень; UUID — смена родителя |
| `GET /work_categories/{id}/view`, `GET /work_categories/all` | `parent_id` в ответе | строка UUID или `null` |

`PATCH .../edit` принимает тело только с `parent_id` (без `name`). Пустой
`name` и тело без `name` и `parent_id` по-прежнему дают `400`.

## Правила валидации (use-case)

При назначении родителя (`add` и `edit`):

1. Категория не может быть родителем самой себя.
2. Родитель должен существовать.
3. Родитель не должен быть мягко удалён (`deleted = true`).
4. Родитель и его предки не должны содержать саму категорию, то есть
   прямые и косвенные циклы (A → B → C → A) запрещены.

Нарушения возвращают `400` с сообщением в `msg`. Неверный формат UUID
тоже даёт `400`.

Цепочка предков читается одним рекурсивным CTE
(`WorkCategoriesManager.get_lineage_ids`). Запрос использует `UNION`, поэтому
он завершается даже на повреждённых данных с циклом.

## Права доступа

Изменения доступны только администратору (`admin_required`), как и раньше.
Разделения категорий по компаниям в сервисе нет, дополнительных проверок
области видимости родителя не требуется.

## Ограничения

Проверка цикла и запись выполняются отдельными шагами без блокировки.
Два одновременных встречных переноса (A под B и B под A) теоретически могут
создать цикл. Операция доступна только администраторам и выполняется редко,
поэтому сейчас этот риск принимается.
