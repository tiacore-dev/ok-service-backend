# Комментарии смен и приёмок

Смены и приёмки имеют независимые неограниченные ленты в таблицах
`shift_report_comments` и `acceptance_comments`. Связи фотографий с общим
хранилищем `attachments` хранятся в `shift_report_comment_attachments` и
`acceptance_comment_attachments`.

Для смен доступны `GET/POST /shift_reports/{shift_report_id}/comments` и
`PATCH/DELETE /shift_reports/comments/{comment_id}`. Для приёмок см. также
`docs/acceptances.md`. Коллекционные ручки принимают `offset` (0 по умолчанию)
и `limit` (50 по умолчанию, максимум 100); порядок стабилен: от старых записей
к новым, затем по UUID комментария. Ответ содержит `total` и `comments`.

POST принимает только `text`; автор, `created_at` в Unix milliseconds UTC и
`browser_id` создания назначаются сервером. Необходимый browser cookie создаётся
по правилам `docs/shift-report-browser-audit.md`. Статус смены и приёмки не
запрещает комментирование. Непустой текст обязателен.

Для смен пользователь пишет только в своей смене, прораб — в смене своей
спецификации, менеджер/администратор — в доступной компании смене. Для приёмок
прораб ограничен своей спецификацией, менеджер/администратор имеют доступ в
компании, исполнитель — если участвовал в работах спецификации приёмки.
Редактирует только автор в течение 5 минут от серверного `created_at`;
обновление не продлевает срок. Удаляет только администратор. API-key permission
проверяется дополнительно и не заменяет эти ограничения.

Файлы загружаются только автором комментария и в пределах тех же пяти минут
после создания, что и редактирование текста. Они загружаются через `POST
/{shift_reports|acceptances}/comments/{comment_id}/attachments` как повторяемое
multipart поле `files`. Сервис применяет обычную проверку файлов S3 attachment.
Список комментариев возвращает metadata вложений; байты открываются через
`GET /{shift_reports|acceptances}/comments/{comment_id}/attachments/{attachment_id}/download`.
Каждый download повторно проверяет право на исходную смену или приёмку.

Удаление комментария или hard delete родительской смены/приёмки удаляет строки
metadata вложений и после успешного commit best-effort удаляет файлы из S3.

Миграция `20261102100000` создаёт обе таблицы комментариев и обе таблицы связей
с файлами. API-key permissions добавлены в bootstrap-каталог; других настроек
нет. Клиентское API не принимает `created_by`, `created_at` или `browser_id`.
