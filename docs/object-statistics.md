# Статистика выполнения работ по объекту

## API

`GET /objects/{object_id}/get-stat`

Метод возвращает `total` и сводные показатели по каждому неудалённому проекту.

Подробный вариант доступен через `GET /objects/{object_id}/get-stat-details`.
Он возвращает ту же структуру `total/projects`, но `stats` каждого проекта и
`total` представлены словарём с ключами `work_id` и детальными показателями,
как в `GET /projects/{project_id}/get-stat`.

Метод доступен аутентифицированным пользователям, кроме роли `user`. В ответе
возвращаются общий итог по объекту и статистика каждого неудалённого проекта
объекта:

```json
{
  "msg": "Object stats fetched successfully",
  "stats": {
    "total": {"project_work_quantity": 100, "presented_quantity": 40},
    "projects": [
      {"project_id": "uuid", "name": "Проект 1", "stats": {}}
    ]
  }
}
```

## Показатели

Статистика проектного метода `GET /projects/{project_id}/get-stat` группируется
по `work_id` и дополнительно содержит:

- `presented_quantity`, `presented_summ` — сумма количества и стоимости всех
  существующих строк `work_acceptance_relations` проекта;
- `accepted_quantity`, `accepted_summ` — сумма количества и стоимости тех же
  связей для приемок со статусом `documents_signed`.

Стоимость каждой связи считается как `quantity × price` соответствующей строки
`project_works`, сопоставленной по `project_id` и `work_id`. Если цена не
задана, сумма получается `null` при отсутствии вычислимой суммы. Нулевые или
отсутствующие acceptance-показатели возвращаются как `null`.

Текущая версия учитывает все существующие приемки и связи: удалённые записи,
отменённые приемки и повторные приемки пока отдельно не исключаются. Это
временное правило и может быть изменено без изменения структуры ответа.

Показатели плана и сменных отчётов сохраняют прежние правила: план берётся из
`project_works`, а факт — из подписанных и неудалённых сменных отчётов.

Объектный метод исключает проекты с `deleted = true`. `total` является суммой
показателей всех включённых проектов; если ни один проект не имеет значения
показателя, в итоге возвращается `null`.

При изменении, создании или удалении приемки либо связи с работой кэш
статистики соответствующего проекта пересчитывается.

## Статистика по прорабу

## Коллекционная статистика

Для экранов со списком всех объектов и всех прорабов доступны:

- `GET /objects/get-stat`;
- `GET /project-leaders/get-stat`.

Оба метода доступны только ролям `admin` и `manager`. Для JWT и API-key
запросов используются отдельные права с точными маршрутами.

Поддерживаются параметры `offset` (по умолчанию `0`), `limit` (по умолчанию
`10`) и `search`. Поиск объектов выполняется по имени, поиск прорабов — по
`login` или `name`. В ответе `total` — итог по всем найденным сущностям,
`total_count` — их количество до пагинации.

Удалённые объекты не возвращаются. В список прорабов входят все неудалённые
пользователи с ролью `project-leader`, в том числе без назначенных проектов.
Для каждого прораба возвращаются `user_id`, `login`, `name` и агрегат `stats`.

Для статистики по прорабу используются отдельные маршруты:

- `GET /project-leaders/{project_leader_id}/get-stat` — общий итог и сводка по
  каждому неудалённому проекту прораба;
- `GET /project-leaders/{project_leader_id}/get-stat-details` — общий итог и
  проекты с детализацией по `work_id`.

Прораб определяется значением `projects.project_leader`. Один проект может быть
назначен только одному прорабу. Если у пользователя нет проектов, методы
возвращают пустые `total` и `projects` без ошибки.

`admin` и `manager` могут запрашивать статистику любого прораба. Роль
`project-leader` может запрашивать только собственную статистику; остальные
роли получают `403`.
