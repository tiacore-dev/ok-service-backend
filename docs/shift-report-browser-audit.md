# Идентификаторы браузера смены

Сервер определяет браузер по UUID из cookie `browser_id` (имя и срок жизни
задаются существующими настройками `BROWSER_ID_COOKIE_NAME` и
`BROWSER_ID_COOKIE_MAX_AGE`). Если cookie отсутствует или содержит некорректный
UUID, сервер генерирует UUID и после успешной операции устанавливает cookie
с атрибутами `HttpOnly`, `Secure`, `SameSite=Lax`.

- `PATCH /shift_reports/{id}/start` записывает `start_browser_id`.
- `PATCH /shift_reports/{id}/finish` записывает `finish_browser_id`.
- `PATCH /shift_reports/{id}/edit` при каждом успешном вызове, включая пустой
  JSON-объект, перезаписывает `modified_browser_id` текущим UUID браузера.
  Основание: требование фиксировать браузер каждого редактирования аналогично
  началу и завершению смены.

Повторный edit из того же браузера сохраняет тот же UUID; edit из другого
браузера заменяет его. Поле не принимается из JSON запроса. Ошибки валидации,
доступа или сохранения не меняют сохранённый идентификатор и не устанавливают
новую cookie. Остальные операции не изменяют `modified_browser_id`.
Существующие права редактирования и ограничения смен сохраняются.

`modified_browser_id` возвращается строкой UUID либо `null` в просмотре и
списке смен и описан в Swagger. Формат ответа самого edit сохраняется.
Миграция `20261021130000` добавляет nullable UUID-колонку без заполнения старых
записей: они остаются с `null` до первого успешного edit. Перед запуском новой
версии нужно применить `alembic upgrade head` в окружении сервиса. Downgrade
удаляет новую колонку вместе с её значениями. Новых настроек нет.
